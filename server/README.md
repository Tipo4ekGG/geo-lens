# Полный geo-sleuth: Oracle Ubuntu + контейнеры инструментов

Это новая серверная реализация. В vendor/geo-sleuth сохранены все 91 файл исходного скилла (27 Python-файлов, данные, справочники, регионы и тесты), без изменения оригиналов. MIT-лицензия и атрибуция таблиц сохранены. Источник и закреплённый commit: vendor/geo-sleuth-source.json.

В отличие от быстрого анализа, сервер запускает intake (EXIF, OCR, обратный поиск), board и выбранные моделью операции карт, панорам, геометрии, рельефа, CLIP/DINOv2/SIFT. Модель читает исходный SKILL.md и справочники и смотрит созданные операторами изображения. Дополнительный web_page.py открывает публичную веб-страницу и сохраняет текст и скриншот. Модель должна поддерживать и изображения, и OpenAI-compatible tool calling; список /models этого не гарантирует.

## Сначала — Oracle
1. Создайте свой аккаунт на https://signup.cloud.oracle.com/. Проверку карты проходите самостоятельно. Бесплатный trial с кредитом и Always Free — разные предложения.
2. В домашнем регионе создайте Compute VM: Ubuntu 24.04, VM.Standard.A1.Flex, только с меткой Always Free Eligible. На дату подготовки документации лимит бесплатных tenancy — суммарно 2 OCPU / 12 GB RAM и до 200 GB boot/block storage. Выделите 80 GB диска, если он укладывается в ваш общий лимит. Без GPU. Проверьте итоговую стоимость в консоли, не выбирайте платные ресурсы или платный upgrade при отсутствии capacity.
3. Сохраните SSH-ключ и подключитесь по SSH к ubuntu@PUBLIC_IP. Приватный SSH-ключ сюда не присылайте. В Security List/NSG достаточно разрешить SSH/22 только со своего IP. Порт 8080 наружу открывать не нужно: сервер слушает localhost и используется HTTPS-туннель.

Официальные условия: https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm. Наличие машины в регионе не гарантировано, idle-машины могут быть отозваны.

## Установка на VM
```bash
git clone https://github.com/Tipo4ekGG/geo-lens.git
cd geo-lens
sudo bash server/deploy/install.sh
```
Скрипт устанавливает Docker, Python API, образ инструментов и systemd. Первая сборка скачивает Chromium, PyTorch CPU и OCR-зависимости; нужны несколько GB и время. Введите фактический полный API base URL (с /v1 или другим путём, который уже работает у вас) и действующий API-ключ в скрытом вводе. Секреты сохраняются только на VM в /etc/geo-lens/server.env (root, 0600), никогда не добавляйте этот файл в GitHub. PHOTO_API_KEY в Worker не копируется автоматически на VM.

Образ multi-architecture на базе python:3.12-slim-bookworm, предназначен для ARM64 и AMD64. Реальная сборка ARM64 и все онлайн-сервисы должны быть проверены на созданной машине. Не считайте тесты с подставным API проверкой реального агрегатора, CAPTCHA, полноты карт или качества ML.

API запускает один анализ за раз, до 3 заданий в очереди. По умолчанию: 32 шага модели, 30 минут на исследование, 10 минут на оператор. Бюджет можно менять в server.env (MAX_AGENT_STEPS, JOB_TIMEOUT_SECONDS, TOOL_TIMEOUT_SECONDS), затем sudo systemctl restart geo-lens. Большая область поиска может потребовать большего бюджета, CPU-ранжирование медленное. Полный скилл не означает гарантированный результат в каждом задании.

## HTTPS без покупки домена: первый тест
Установите cloudflared по официальной инструкции для вашей архитектуры: https://developers.cloudflare.com/tunnel/downloads/.
На VM, во второй SSH-сессии:
```bash
cloudflared tunnel --url http://127.0.0.1:8080
```
Скопируйте выданный HTTPS-адрес *.trycloudflare.com. Quick Tunnel не требует домена, но предназначен для тестирования: нет uptime-гарантии, URL меняется при перезапуске, сессия должна продолжать работать. Для постоянного сайта используйте named Cloudflare Tunnel и свой домен; серверный код тот же. Нельзя передавать токен backend через публичный HTTP.

## Связь с существующим Worker
В Cloudflare → geo-lens-api → Settings → Variables and Secrets:
- FULL_BACKEND_URL (Text): выданный HTTPS URL без завершающего /.
- FULL_BACKEND_TOKEN (Secret): значение BACKEND_TOKEN с VM. Просмотрите его только у себя: sudo cat /etc/geo-lens/server.env; не отправляйте файл или вывод в чат. Другие секреты Worker сохраните.

Перепубликуйте Worker, если Cloudflare попросит. На сайте выберите «Полный geo-sleuth», укажите контекст/цель, выберите vision+tools модель, запустите анализ. Оригинал передаётся на VM; модель получает уменьшенную копию. Задания опрашиваются короткими запросами (нет ожидания 30 минут в одном Worker-запросе). Можно отменить анализ и скачать артефакты. Старый быстрый режим остаётся отдельным вариантом, автоматического отката на него нет.

## Хранение и изоляция
Фото, команды, промежуточные изображения и отчёты хранятся до 24 часов; очистка выполняется при обращениях к API. Не обещается удаление ровно через 24 часа при выключенном/неиспользуемом сервере. Файлы исчезают после очистки или удаления диска. Доступ к API — только по отдельному BACKEND_TOKEN, а из браузера — через прежний ACCESS_TOKEN Worker. Один токен означает одно общее личное пространство, не многоарендный сервис.

Каждый оператор запускается в новом Docker-контейнере: только текущая папка задания, общий кеш весов, read-only корень, ограничение памяти/CPU/процессов, без API-ключа и backend-токена. Host Docker socket в контейнер не передаётся. Подсеть инструментов блокируется от private/link-local адресов, включая metadata Oracle. API-service входит в группу docker: это доверенный сервис владельца; не давайте посторонним SSH-доступ к его пользователю. Старый код скилла исполняется без изменения. Для вложенных вызовов uv run служит адаптер server/skill-uv: он запускает Python с заранее установленными зависимостями в образе. refresh.py не может обновлять read-only пакет во время исследования; обновление исходников выполняется владельцем с пересборкой образа.

Нельзя считать board check доказательством абсолютной точности. Сервер прикладывает board-report.json и команды; если board check не пройден, нет главного кандидата с сохранённым read/computed evidence, итог помечается низкой уверенностью и координаты модели удаляются. Содержимое фото/веб-страниц считается недоверенными данными. Сервис для личного использования, а не публичная загрузка произвольных заданий.

## Диагностика
```bash
sudo systemctl status geo-lens --no-pager
sudo journalctl -u geo-lens -n 80 --no-pager
curl http://127.0.0.1:8080/health
sudo -u geolens docker run --rm --network geo-tools --shm-size 512m geo-lens-tools:local python /opt/skill/scripts/doctor.py --json
```
Доктор проверяет браузер и данные, но не скачивает ML-веса и не доказывает работу загрузки фото на поисковые сервисы. Первые ML-веса загружаются при вызове match/sat_scan. CAPTCHA/403, ограничения API и несуществующие панорамы показываются как ошибки инструментов. Поддержка tool calling проверяется первым полным заданием. Регистрация Oracle/создание VM и деплой из этой среды пока не выполнялись.
